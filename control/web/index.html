Live RDMA configuration

Trust boundaries

Security and access

Operator access

  • Private VM with no public IP
  • OCI Bastion for UI forwarding and break-glass SSH
  • Instance principal instead of a user OCI API key
  • Source-restricted NSG and host-firewall rule for the private UI
  • Deployment-specific workspace token for the private UI

RDMA operations

  • SR-IOV/VF path only
  • PF/MTU discovered from live node state
  • Node and Cloud Agent status queried read-only through APIs
  • Typed approval before VF/node reconfiguration
  • No privileged or host-network validation pods
  • Immutable validation image required for live RDMA test
